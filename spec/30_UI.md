## 4. Bản đồ bài học (cột trái)

- ReactFlow dùng `node.position` từ engine (INV-10); `nodesDraggable`, `nodesConnectable`, `elementsSelectable = false`; Controls góc dưới trái. Mở: vừa khung nếu đọc được, không thì phóng quanh node đang mở hoặc node `AVAILABLE` đầu tiên; mở bài ⇒ đưa node đó vào giữa khung.
- Bấm node không `LOCKED` ⇒ mở bài (7.4); nút "Thử lại phân tích" trong node vẫn bấm được.
- **Màu theo `status` (INV-11):** nền, viền, chữ lấy từ `--st-*`, thẻ có vạch màu bên trái và nhãn trạng thái. `LOCKED` viền đứt mờ, 🔒 "Chưa mở" · `AVAILABLE` nhịp sáng, ● "Sẵn sàng" · `COMPLETED` ✓ "Hoàn thành" · `FAILED` ✗ "Chưa đạt" (giữ đỏ, không ôn — D-35).
- **Lớp hiển thị:**
  - `has_warning` ⇒ ⚠ trên trái, tooltip "Node trước chưa vững: {node cha FAILED / phân tích lỗi}".
  - `"PENDING"` ⇒ xoay + "đang phân tích…"; `analysis_failed` / `"FAILED"` ⇒ "Chưa phân tích được" + "Thử lại phân tích" (UI-73).
  - `is_capstone` ⇒ ★ "Capstone"; `ALGORITHMIC_CORE` ⇒ "Thuật toán" `--violet`; node đang mở viền ngoài màu `--ink`.
- **Tên:** `title_source ∈ {DOMAIN_TERMS, DIRECTORY, FILE_BASENAME}` ⇒ tiền tố "~"; dài quá `CONFIG.TITLE_MAX_CHARS` ⇒ cắt + "…". Tooltip: tên đủ + `title_evidence` + "Tên suy ra — gần đúng"; `VIRTUAL` ⇒ "Chặng tách từ hàm dài — code thật, engine chia theo vai trò câu lệnh". Dòng phụ "{files.length} file · {languages}".
- **Cạnh (`FlowEdge`):** `RESOLVED` nét liền; `INFERRED` nét đứt, `aria-label` "Cạnh suy luận — chưa bảo đảm 100%", chú giải có tooltip. Màu nét theo nguồn khi `COMPLETED` / `FAILED`, còn lại xám.
- **Chuyển động cạnh:** lớp phủ riêng, vệt sáng + chấm chạy theo hướng học, màu theo nguồn (`AVAILABLE` vàng); nguồn `LOCKED` chỉ có chấm mờ chạy chậm; cạnh nối node đang mở có quầng sáng. Không dùng `animated` của xyflow, nét đứt chỉ mang nghĩa suy luận.
- **Đầu cột:** "Bản đồ bài học", "{n} node"; chip "Độ tin cậy đồ thị: Cao / Vừa / Thấp" (`graph_confidence`, xanh/vàng/đỏ); `language_breakdown` "{language} {% code_bytes}" + "· suy luận" nếu `STRUCTURAL`; `detected_framework`; `degraded_mode` ⇒ "Repo tuần tự"; "Đã che {redacted_secret_count} nội dung nhạy cảm"; "Bỏ qua {n} file ▾" mở popover `skipped`. Dưới đó là dải cảnh báo: `truncated` / `warnings` / `omitted_node_count > 0` ("{n} luồng khác không hiển thị trên bản đồ" — D-53), mỗi dòng đóng được (`LOW` không đóng được), trừ cảnh báo thời gian `engine_ms`.
- **Node `LOCKED`:** Bấm/Enter không làm gì (0 request, `cursor: not-allowed`, `aria-disabled`), tooltip "Hoàn thành trước: {node cha chưa thông}".
- Chú giải cuối cột: 4 trạng thái, ⚠ "Node trước chưa vững", cạnh chắc chắn / suy luận.

## 5. Code (Monaco, chỉ đọc)

- Model node: Các bước nối tiếp, mỗi bước 1 tiêu đề + `snippet`, cách dòng trống: `// ── Bước 2 · BUSINESS_LOGIC · src/services/product.service.ts · listProducts [· origin_note]` (`#` với Python). Cuối: "Kiểu dữ liệu" = `dto_snippet` (bỏ nếu rỗng). `buildSliceModel(node) → { text, lineMap, stepRanges }` ở `src/components/code/slice-model.ts`.
- **Số dòng gốc (UI-31):** `lineNumbers: n => lineMap[n-1] > 0 ? String(lineMap[n-1]) : ""` (từ `lineMap`, `snippet_line_map`); tiêu đề, dòng trống, marker (`0`) và kiểu dữ liệu không số; marker mờ.
- **Tô sáng (UI-32):** Bước chọn (`stepRanges[active_step]`) nền vàng nhạt + vạch `--amber`; bước trong `analysis.weak_points` vạch `--red` + glyph ⚠ ở tiêu đề, hover "Nhận định của AI: {what}"; gợi ý `CODE_POINTER` (`ui.hint_step`) vạch `--violet` + glyph 💡, cuộn tới.
- **Đồng bộ 2 chiều (UI-33):** Bấm bước/kỹ năng/điểm dở ở X-Ray, dòng ở bảng dưới hoặc chip bước ⇒ `active_step = k` ⇒ `revealLinesInCenter`. Bấm editor ⇒ `active_step` = bước chứa dòng đó ⇒ X-Ray tô bước đó. Không đồng bộ theo cuộn.

## 6. X-Ray, Feynman, Tổng quan

Vừa nạp phiên, chưa chọn node ⇒ cửa sổ Tổng quan tự mở; đóng lại thì cột giữa và cột phải nhắc chọn node (cột phải có "Mở Tổng quan kiến trúc"). Chọn node ⇒ hiện code, tab X-Ray. Tab Feynman (`active_tab`, có số câu chưa xong) bật khi `analyses[id]` là bản phân tích; đang chờ `enrich-node` ⇒ xoay; tắt ⇒ tooltip "Chọn một node trước" / "Cần bản phân tích trước khi đặt câu hỏi".

### 6.1. X-Ray

- Thứ tự: Đầu node (tên đủ, `title_evidence`, ★/⚠/Thuật toán, `support_tier`) → Kỹ năng → Kiến trúc → Luồng → Điểm hay → Điểm dở → Liên quan → Chỉ số → nút.
- Kỹ năng của node đang mở: Chip `skills[i]` gồm mã, điểm decay (`getDecayedMastery`, 4 chữ số), `tierOf`. Hover: "Vì: {reason} — bước {step} · `{symbol}` · {file_path} dòng {line_start}–{line_end}"; bấm ⇒ `active_step = step`.
- **Mài mòn kiểu Duolingo (D-35, `22` BKT-24, chỉ hiển thị):** mỗi chip có thanh dài theo điểm đã decay (`now = Date.now() + server_clock_offset_ms`), độ đậm tỉ lệ `điểm đã decay / p_mastery` (nhạt dần liên tục khi lâu không luyện); `isDecaying` (bậc `tierOf` của điểm đã decay thấp hơn bậc của `p_mastery`) ⇒ nhãn "đang mài mòn"; đã decay mà chưa rớt bậc ⇒ chỉ thanh nhạt, không nhãn + tooltip "Điểm gốc {p_mastery} — đã giảm còn {điểm đã decay} vì lâu chưa luyện". Không có nút ôn, không đổi màu node. Tính lại khi `profile` đổi.
- Kiến trúc: `patterns` (đầu là chính) + `summary`. Nhãn: `LAYERED` Tách tầng · `MIDDLEWARE_CHAIN` Chuỗi middleware · `DEPENDENCY_INJECTION` Tiêm phụ thuộc · `OBSERVER_EVENT` Observer · `PIPELINE` Chuỗi xử lý · `ALGORITHMIC` Thuật toán · `PROCEDURAL` Tuần tự · `OTHER` Khác; còn lại giữ tiếng Anh.
- Luồng: Mỗi `steps[i]`: số, `layer`, file, "dòng {line_start}–{line_end}", `function_name` (`trace_steps`), `text` (`null` ⇒ bỏ). Bước chọn tô vàng, bấm ⇒ `active_step`; điểm dở mang ⚠.
- `ALGORITHMIC_CORE`: Stepper `ALGO_SETUP` "Khởi tạo" → `ALGO_EXECUTION` "Vòng lặp chính" → `ALGO_TERMINATION` "Điều kiện dừng"; chặng trống mờ.
- Điểm hay/dở: "✅ (bước {step}) {text}". Điểm dở: viền đỏ, tiêu đề **"Điểm dở — Nhận định của AI"** + "{file_path} dòng {line_start}–{line_end}" + kỹ năng; thân `what` + "Hậu quả: {consequence}". Cấm hiện cách sửa, con số tình huống, biên (INV-06); không ghép nguồn khác.
- Khác: `shared_files` ⇒ mục "Liên quan": "Dùng chung {basename} với {chip node}". Chỉ số: `uncle_bob` I · A · D + `diagnosis` (`is_exempt` ⇒ "Miễn trừ") + `cognitive_complexity`. `skeleton_only` ⇒ "AI chưa giải thích được node này — chỉ hiện khung do code dựng", ẩn phần Kiến trúc. Chưa có bản phân tích hoặc `"PENDING"` ⇒ khung từ `trace_steps` + shimmer "đang phân tích…"; `"FAILED"` ⇒ "Chưa phân tích được" + "Thử lại phân tích".
- **Nút cuối X-Ray (UI-47):** ghim ở đáy cột. `AVAILABLE` chưa xong run ⇒ "Bắt đầu trả lời ({số câu chưa xong, trừ DROPPED}) →", chưa có run thì không có số ⇒ `active_tab = "FEYNMAN"` (chờ enrich ⇒ "Đang chuẩn bị câu hỏi…"; lỗi ⇒ "Thử lại"). `COMPLETED` / `FAILED` ⇒ không có nút (không ôn tập — D-35), chỉ dòng "✓ Đã hoàn thành node này." / "✗ Node này chưa đạt." + "Xem lại câu hỏi ở tab Feynman. Không có ôn tập: node giữ nguyên màu."

### 6.3. Cửa sổ Tổng quan

3 giai đoạn (D-71, UI-78); 1–2 tính trên client, 0 API. Đóng bằng ✕, `Esc`, bấm nền hoặc bấm chip node để mở bài:

## 7. Trạng thái & luồng gọi API

### 7.1. Store

`ClientWorkbenchState` theo 7.3–7.6; đổi phiên ⇒ reset phiên. `last_failed_answers` mất khi tải lại. `server_clock_offset_ms` = `server_now − Date.now()` ở mỗi `MeResponse`. Slice `ui` (tạm): `auth`, `user`, `boot_error`, `pending` (VD `enrich:{node_id}`, `submit:{run_id}:{question_index}`), `last_evaluations`, `last_changes`, `drafts`, `sessions`, `metrics`, `presentation`, `hint_step`, `offline_persona`, `toasts`, `overview_open`, `ingest_error`, `ingesting`, `submit_error`, `newly_unlocked`, `quota_stopped`. Bố cục và chủ đề ở store riêng `useLayout`, `useTheme`. Bỏ response mang `session_id` khác phiên hiện tại.

### 7.2. Khởi động

`Boot` chạy 1 lần cho cả app: nạp chủ đề, gắn `Ctrl+Shift+D`, gọi các bước dưới. `/learn?session={id}` khi chưa có phiên ⇒ `POST /api/ingest { session_id }`, mỗi `id` thử 1 lần, lỗi ⇒ báo + "Về trang chủ".

1. `?offline=1` ⇒ Mục 8, dừng.
2. `supabase.auth.getSession()`; chưa có ⇒ hiện màn hình "Đăng nhập GitHub" (bấm ⇒ `signInWithOAuth({ provider: "github" })`).
3. `GET /api/me` ⇒ `profile`, `server_clock_offset_ms`.
4. `GET /api/sessions` ⇒ "Tiếp tục học".
5. `sf.last_session` có và `can_resume` ⇒ `POST /api/ingest { session_id }`; lỗi ⇒ báo 10, `ERR_SESSION_NOT_FOUND` xóa `sf.last_session`. Lỗi bước 3 ⇒ trang chủ hiện thông điệp lỗi + "Thử lại" + "Mở bản demo Offline".

### 7.3. Hàng đợi phân tích & tổng quan

- Ingest xong ⇒ thay `session_id`, `result`, `progress`, `analyses`; `runs = {}`, `overview = null`; đưa 2 node đầu theo tô-pô chưa có bản phân tích vào hàng.
- Chỉ gọi `analyze-node` cho node đang mở và 1–2 node kế tiếp (D-46). "Kế tiếp" = thứ tự tô-pô sau node đang mở (hòa ⇒ `id` tăng), bỏ qua node đã có bản phân tích. Node vào hàng ⇒ `"PENDING"`; node chưa vào hàng không có nhãn. Tối đa `CONFIG.ANALYZE_CONCURRENCY` lời gọi đồng thời. Bấm node khác ⇒ chuyển ưu tiên sang node vừa chọn và 1–2 node kế tiếp của nó.
- Response: `analysis` ⇒ `analyses[id]`, `null` ⇒ `"FAILED"`; áp 7.5. `ERR_TOKEN_QUOTA_EXCEEDED` ⇒ dừng hàng, node chờ ⇒ `"FAILED"`. Lỗi khác ⇒ `"FAILED"` node đó, hàng chạy tiếp.
- "Thử lại phân tích" ⇒ `"PENDING"` + đầu hàng (UI-73).
- Mọi node có bản phân tích hoặc `analysis_failed` (theo server) ⇒ `POST /api/analyze-overview` đúng 1 lần (UI-74). `ERR_OVERVIEW_NOT_READY` ⇒ im lặng, gọi lại sau phân tích kế tiếp.

### 7.4. Bấm node (không `LOCKED`)

1. `active_node_id = id`, `active_step = 1`, `active_question_index = null`, `active_tab = "XRAY"`, `ui.hint_step = null`, `ui.submit_error = null`, đóng cửa sổ Tổng quan. X-Ray hiện ngay; chưa có bản phân tích ⇒ `"PENDING"` + đầu hàng.
2. Gọi nền `enrich-node` (`LEARN`) khi có phân tích, `runs[id]` không có run chưa xong, không có `ui.pending["enrich:"+id]`, và: `AVAILABLE` ∧ chưa run; hoặc `last_run.finished_at = null` (server trả đúng run đang mở). Phân tích về sau ⇒ gọi nếu node mở.
3. Response ⇒ `runs[id]`, áp 7.5, `active_question_index` = câu chưa xong đầu.

### 7.5. Áp response

- `node_state` ⇒ `progress.nodes[node_id]`; `tokens_used` ⇒ `progress.tokens_used`; `question` ⇒ `runs[node].questions[k].state`.
- `skill_change ≠ null` ⇒ chip (UI-54) rồi `GET /api/me`. `profile` chỉ thay bằng `MeResponse`, `PersonaResponse`.
- `unlocked_node_ids` khác rỗng **hoặc** `node_state.status` vừa đổi ⇒ `GET /api/sessions/{id}/progress` ⇒ thay `progress` (mở khóa, `has_warning` node khác) (UI-76); node vừa mở hiệu ứng.
- **Lỗi khi nộp / bỏ qua / báo sai (UI-77):** `ERR_ATTEMPT_OUT_OF_SYNC` / `ERR_QUESTION_FINISHED` ⇒ im lặng `enrich-node` (lỗi `NODE` ⇒ UI-76) + toast "Câu này vừa được nộp ở tab khác", giữ nội dung ô. `ERR_PERSISTENCE_UNAVAILABLE` ⇒ không lưu tạm ở client, giữ nội dung ô + "Thử lại" (D-40).

## 11. Truy cập, responsive, token thiết kế, hiệu ứng

**Token (D-67, D-79):** CSS var theo `html[data-theme]` trong `globals.css`, map vào `@theme inline`. Mặc định `dark`; nút ☀/☾ lưu `sf.prefs.theme`, `theme-script.ts` gán trước khi vẽ nên không nháy màu.

| Token | Tối | Sáng |
| :-- | :-- | :-- |
| `--bg` | `#09080f` | `#f8fafc` |
| `--panel` / `--panel-2` | `#12101a` / `#0d0b14` | `#ffffff` / `#f1f5f9` |
| `--text` / `--muted` / `--subtle` | `#eeecf6` / `#a5a0bb` / `#807b97` | `#0f172a` / `#475569` / `#64748b` |
| `--amber` / `--green` / `--red` | `#f5b942` / `#34d399` / `#fb6185` | `#b45309` / `#15803d` / `#b91c1c` |
| `--locked` / `--violet` / `--blue` | `#6a6580` / `#b69cff` / `#6ea8ff` | `#64748b` / `#7c3aed` / `#1d4ed8` |
| `--accent` / `--accent-2` | `#8b5cf6` / `#e04fa0` | `#9333ea` / `#4f46e5` |

`--accent` cho nút chính, tab, focus, thanh kỹ năng, không mang nghĩa trạng thái. Bộ `--st-{done,ready,fail,lock}-{bg,border,fg}` cho thẻ node, nhãn trạng thái, thẻ số liệu. `--ink`: trắng ở nền tối, mực tối ở nền sáng; `--line*`, nút, bóng đổ, nền phát sáng khai báo đủ trong `globals.css`. Font: Plus Jakarta Sans, JetBrains Mono qua `next/font/google`. Kính mờ `.glass` cho toast, popover, hộp thoại; cột, thẻ nền đặc.

- **Bàn phím:** Focus theo thứ tự `result.nodes`, Enter/Space mở; `Ctrl+Enter` nộp, `Esc` thoát trình chiếu/hộp thoại; phím bố cục ở Mục 2.2; viền `--accent` luôn thấy.
- **Đọc màn hình:** `aria-label` node = "{tên} — {trạng thái}[, có cảnh báo][, đang phân tích]"; kết quả chấm, lỗi, toast trong `aria-live="polite"`.
- **Độ tương phản:** WCAG AA trên `--bg` / `--panel` ở cả 2 chủ đề; chữ trên `--amber` dùng `--on-amber`.
- **Responsive:** Từ `lg` ⇒ 3 cột; nhỏ hơn ⇒ 1 cột; không cuộn ngang.
- **Cửa sổ:** Cao tối đa màn hình trừ lề, tiêu đề và nút luôn thấy, thân cuộn.
- **Hiệu ứng (CSS thuần):** Nhịp sáng `AVAILABLE`; `transition-colors` khi đổi màu; đổi chủ đề chuyển màu mềm; node vừa mở khóa phóng nhẹ 1 lần; chuyển động cạnh (Mục 4); shimmer khung chờ; thanh điểm chạy chiều rộng; toast trượt vào; ô trả lời rung khi có lỗi; khung, tab, hộp thoại hiện mềm; nút "Bắt đầu trả lời" phát sáng. `prefers-reduced-motion: reduce` ⇒ tắt hết, không vẽ lớp chuyển động cạnh, chỉ đổi màu.
